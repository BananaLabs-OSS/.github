# Contributing to BananaLabs OSS

Thank you for contributing.

## Before opening a change

- Check existing issues and pull requests for related work.
- Open an issue first for substantial behavior or architecture changes.
- Keep changes focused and avoid unrelated formatting churn.
- Never commit credentials, private keys, personal data, or generated local
  workspace metadata.

## Development

Follow the repository's README and local contributor instructions. Run the
relevant formatter, tests, and build before submitting a pull request. Add or
update tests when behavior changes.

Commits should use a concise conventional form such as `fix:`, `feat:`,
`docs:`, `test:`, or `chore:`. Do not add `Co-Authored-By` trailers unless the
named contributor explicitly requests attribution.

## Pull requests

Describe the problem, the solution, validation performed, and any security,
compatibility, migration, or deployment impact. By contributing, you agree
that your contribution is provided under the repository's license.
